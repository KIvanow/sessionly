Sessionly records what coding agents did — Claude Code, Codex, Cursor, Grok and OpenCode, on a
machine or in the cloud — in one session record, and says per pull request what it cost and how
many of the agent's lines survived review. Site and live demo: [sessionly.dev](https://sessionly.dev/).

## What changed since 0.8

- **OpenCode.** Sessions of OpenCode are read from its database, `opencode.db`, which is opened
  read-only: prompts, tool calls, files and lines changed, child sessions folded into the
  session that started them, tokens per step, and OpenCode's own cost, or an estimate where it
  recorded none. `sessionly install` writes a plugin into OpenCode's config folder that notes
  each session and starts the automatic sync when one goes idle. `sessionly import --tool
  opencode` brings in the sessions from before. What is read, and what is not, is on
  [docs.sessionly.dev/opencode.html](https://docs.sessionly.dev/opencode.html). (#72, #73)
- **Who served a model.** A session's usage keeps the model as its maker names it
  (`claude-sonnet-4-5`) and, where the agent records it, who served it as `provider`
  (`anthropic`, `openrouter`, `ollama`). The session page shows it beside the model. (#72)
- The website lists OpenCode with the other agents, says what the hosted service's own parts
  are, and may be shown in a frame by nicklaunches.com. (#70, #71)

## When you upgrade

- **Run `sessionly install` again** on a machine with OpenCode, so that its plugin is written.
  Until then `sessionly status` says the plugin is missing.
- **The first sync imports OpenCode's past sessions** once the plugin has seen one, or with
  `sessionly import --tool opencode`. Each is then uploaded.
- **A server older than 0.9.0 takes uploads from this version.** It keeps the new `provider`
  field in what it stores, and shows it once it is updated.
