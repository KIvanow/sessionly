Sessionly records what coding agents did — Claude Code, Codex, Cursor and Grok, on a machine or in
the cloud — in one session record, and says per pull request what it cost and how many of the
agent's lines survived review. Site and live demo: [sessionly.dev](https://sessionly.dev/).

## What changed since 0.7

- **Review runs.** A session's record lists each time a review command ran in it
  (`/code-review`, `/review`, `/security-review`, `/ultrareview`, Codex's `/review`): when,
  how it was started, the effort, the pull request it named, its subagents and their cost, and
  how many findings it reported. A pull request's page shows the runs of its sessions in
  order, beside the review bots' comments. (#62)
- **Who asked for each round of review.** A pull request's page has a row for each reviewer,
  people and bots apart from the author, and how many rounds followed only bots' feedback,
  only people's, or both. The pull requests page adds a Review bots table. This needs version
  0.4.0 of the GitHub Action, which the server now names as the current one. (#64)
- **Grok's subagents.** A subagent Grok starts is read into the session that started it, with
  its tool calls and its own cost, instead of being a second session whose cost was already
  in the first. Grok's `/review` has its reviewer, what it cost and how long it took. (#66)
- **A server of your own opens its dashboard without signing in.** Whoever can reach the server
  is its admin, so keep it where only you can. Uploads still take a token. Google and GitHub
  sign-in are for the hosted service only, and stop working on a server of your own;
  `SESSIONLY_HOSTED` must be `true`, `false` or unset. (#63)
- **The hosted service is under LICENSE-EE.** Signing up, Google and GitHub sign-in, adding
  people by address, deleting organisations and the demo are in `ee/`. The core stays a
  complete server of your own, and refuses to start with `SESSIONLY_HOSTED=true`. The
  published image includes `ee/`, as before. (#65)
- A shared link to the dashboard has a title, a description and an image on Twitter too.
  (#60, #61)

## When you upgrade

- **The first sync takes longer.** The ledger's layout changed, so it is rebuilt, and every
  agent's past sessions are imported again so that they get their review runs. Each session is
  then uploaded once more. Nothing is lost: the ledger is made from what is on the machine.
- **A Grok subagent uploaded as a session of its own stays on the server.** The rebuilt ledger
  no longer knows it was uploaded, so it is not taken back: delete it there by hand. Its cost
  is also in the session that started it.
- **Repositories that report with Action 0.3.0** are told to move to 0.4.0. Until they do,
  their pull requests say that whose feedback each round followed is not known.
